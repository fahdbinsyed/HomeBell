The story

What HomeBell does, in one afternoon

Schools lose a lot of time at dismissal: cars queue at the gate, staff shout names, and children wait without knowing who is coming. HomeBell lets parents tell the school they're on the way, so the child's class knows and the child is ready when the parent arrives.

  1. Before termHomeBell teamcreates the school in the Platform console.
  2. Setup weekSchool adminadds students, parents and the gate TV.
  3. 2:55 pmParenttaps "Request pickup" in the phone app.
  4. 2:56 pmGate TVlists "Mia R." under Grade 2, so her class knows she's being collected.
  5. 3:02 pmParentcollects Mia at the gate. No staff action is needed.
  6. 3:04 pmParentconfirms "Mia is with me" in the app. Her name leaves the TV. Done.

Show the apps in this order. The demo works best in the order the story happens.

Before you start

Start the apps

Open a terminal in the project folder (C:\NeuXPlus\Homebell) and start each web app. Each one needs its own terminal window. 

pnpm --filter @homebell/web-platform dev     # http://localhost:3001
pnpm --filter @homebell/web-school dev       # http://localhost:3000
pnpm --filter @homebell/web-display dev      # http://localhost:3002

For the parent app, open the HomeBell development build on the Android phone, then start Metro on the laptop. The phone and laptop must be on the same Wi-Fi. 

pnpm --filter @homebell/mobile-guardian start

Tip: open each web app once before your brother arrives. The first page load takes 10–20 seconds while it compiles; after that, pages switch instantly.

localhost:3001

Platform console

Used by the neuXplus team, never by schools. This is where schools are created, put on trial, switched to paid, or suspended.

Sign in owner@homebell.test demo1234 MFA 000000
  1. Sign in. You'll get a second step asking for a 6-digit code; enter 000000.Say: platform staff always use two-step verification, because this console can switch off any school.
  2. On Schools, point out the status column (Active, Trial, Suspended) and the warning flags.Each school is a separate, sealed-off tenant. One school can never see another's data.
  3. Click Create school. Type a name; the address fills itself. Pick a time zone (Qatar, Kuwait, India and others are listed), term dates, and a trial end date. Add a contact.The grey line beside the button lists what's still missing, so you're never stuck with a greyed-out button.
  4. Create it. Open the new school's Lifecycle tab: history shows "Created → Trial, reason Trial requested".Every change of state needs a reason and is recorded for audit.
  5. Open Greenfield Academy and walk the tabs: Overview, Plan & subscription, Entitlements, Usage & limits, Notes, Audit.
  6. Try Suspend on a test school, then Reinstate it.
  7. Open Support sessions and start one for Greenfield. A new tab opens the school dashboard in a read-only support view with a purple banner.Support can look, but can't change anything, and the school can see that support was in.
  8. Finish with Device transfers and Audit log.This is where we catch parents trying to share one login across phones.

App 3 of 4

localhost:3002

Display screen

Runs full-screen on a TV at the gate or in the lobby. It has no login: it's paired to one school once.

  1. Open it. A large pairing code and QR code appear.
  2. Click Use the demo Greenfield Academy screen in the yellow box.
  3. The board has one fixed row per grade (Grade 1, Grade 2 …), always in the same order, with the requested names flowing to the right, oldest first. A name waiting more than 10 minutes turns amber with its minutes, and the footer asks staff to follow up.This screen is for teachers, dismissal staff and students. Parents use the app. Students look along their own grade's row for their name. Only first name and last initial are shown, never phone numbers or parent names, because anyone near the screen can see it.
  4. To show a busy afternoon, click Mock · Default, choose Busy queue: about 30 children across five grades. If the pairing screen appears, click Use the demo Greenfield Academy screen again.A name leaves the board once the parent confirms pickup (or staff mark the child sent out, if the school uses that step). If the grades don't fit on one screen, the board pages through them every 9 seconds and shows "Page 1 of 2 · Grade 1 A – Grade 3 A".
  5. Press F11 for full screen, the way it looks on a real TV.

Good to know

Demo limits

The four apps don't talk to each other yet. Each app runs on its own demo data, so a pickup requested on the phone won't appear in the school's Live queue. Tell the story across the apps, but don't wait for a request to jump from one screen to another. Connecting all four to the real server is the next phase.

Already built

The real server (database, logins, SMS codes, tenant isolation, audit) is finished and passes 82 automated tests. It just isn't connected to the apps yet.

Resetting the demo

Switching scenario in the Mock · Default panel resets that app's demo data. Use it if things get messy mid-demo.

iPhone

The same app is built for iPhone, but it hasn't been tried on a real iPhone yet. Show it on Android.

Pre-Phase 3 review

What the review fixed

Before this walkthrough, every screen of the four apps was clicked through and these problems were fixed:

  • Opening a school from a support session always failed in development. It now opens the read-only support view.
  • With two tabs of the same app open, refreshing one could sign you out. Tabs now stay in sync.
  • Lists (students, guardians and others) now work with the keyboard, and names are real links you can open in a new tab.
  • The create-school form now lists missing fields instead of only greying out the button. It also gained Gulf and India time zones.
  • New schools no longer get a "No recent activity" warning in their first two weeks, and their history reads "Created / Trial requested".
  • Audit filters read in plain words ("SMS code sent" instead of "Otp sent").
  • The parent app now asks for confirmation before cancelling a pickup or moving the account to a new phone. Sending a new SMS code clears the old error.
  • The floating Next.js badge no longer covers the menu during demos.
